Write all three artifacts to `.kiro/specs/circuit-seance/`: `requirements.md`, `design.md`, `tasks.md`. Do not write application code yet and do not run git commands.

Feature: the full MVP of Circuit Séance as described in `.kiro/steering/product.md`, `tech.md`, and `structure.md`.

Answers to the clarifying questions you would normally ask:
- Scope: one MVP spec covering capture/upload -> vision LLM transcription to SPICE netlist -> editable netlist with validation -> in-browser ngspice WASM simulation (eecircuit-engine in a Web Worker) -> green-phosphor CRT oscilloscope display -> AI "spirit" plain-language explanation. Plus bundled example circuits that work with no API key.
- Analyses: .tran must be first-class on the scope (time on x-axis, up to 4 channels/probes selectable). .ac shown as Bode magnitude/phase on the scope (log frequency). .dc sweep shown as X-Y. .op shown as a node-voltage readout panel.
- LLM: provider-agnostic adapter; OpenAI-compatible (image input) and Anthropic Claude adapters. User's own API key stored only in browser localStorage, never sent anywhere except the chosen provider. Vision output must be a netlist inside a fenced block plus a confidence note; the app validates it (syntax + element/node checks + ngspice dry run) and highlights problem lines before simulation. Give the user a side-by-side view of the photo and the netlist.
- Spirit explanation: receives the netlist, analysis type, and a compact numeric summary of results (not raw arrays): e.g. min/max/final values, estimated time constant, rise time, overshoot, -3 dB frequency. Explains at an undergraduate level, in English or Simplified Chinese per UI language, and suggests one "try next" experiment. Must degrade gracefully with a rule-based offline explanation for the bundled examples when no key is set.
- CRT scope design: green P31 phosphor look, glow (bloom), persistence/afterglow trails, faint scanlines and flicker, graticule with 10x8 divisions, volts/div and time/div knobs, channel colors in phosphor tints. Must respect `prefers-reduced-motion` (disable flicker/animation) and stay readable (WCAG AA contrast for text). 60 fps target on a mid-range laptop for <=10k points.
- Error handling: simulation errors from ngspice (e.g. singular matrix, missing ground, timestep too small) are caught and translated into friendly "the spirits are restless" messages with the actual ngspice message available, and the spirit can suggest fixes (e.g. "add a ground node 0").
- Performance: engine loads lazily (~40 MB package; WASM should be fetched once and cached); simulation must not block the UI thread; show a "summoning…" loading state.
- Mobile: works on a phone browser for capture (camera input via `<input type=file accept=image/* capture=environment>`), scope usable in landscape.
- i18n: English and Simplified Chinese UI strings.
- Out of scope: accounts, backend database, schematic drawing editor, PCB.
- Testing: Vitest unit tests for netlist parser/validator, result summarizer, and LLM response parsing; property-based tests (fast-check) for the netlist parser round-trip; one Playwright e2e smoke test that loads an example, simulates, and sees a trace.

Requirements must use EARS notation for acceptance criteria (WHEN/IF/WHILE/WHERE ... THE SYSTEM SHALL ...), grouped as numbered user stories. Design must include architecture overview, a mermaid component diagram and a sequence diagram for the photo->netlist->simulate->explain flow, data models/TypeScript interfaces, worker message protocol, error handling, and testing strategy. Tasks must be a numbered checkbox list (`- [ ] 1.`, sub-tasks `- [ ] 1.1`), each task small and referencing the requirement numbers it satisfies (`_Requirements: 1.2, 3.1_`), ordered so the app is demoable early (examples + simulation + scope before the LLM features).
